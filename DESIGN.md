# Design System: McGill Institute Australia — OLED redesign of "Parramatta Transit"

## Overview (2026-10-22, full visual-system redesign)

A client brief asked for a full HTML/CSS/JS rebuild into an "award-worthy" experience: a full-screen photo hero slider, strict alternating OLED-black/off-white sections, a glassmorphic floating nav, magnetic CTA buttons with a cursor light-flare, 3D-tilt cards, an asymmetrical Bento grid, and scroll-driven reveals. Per the Impeccable redesign workflow, this **replaces** the prior "Parramatta Transit" indigo/paper palette and its `prefers-color-scheme` + manual toggle dark mode — but keeps the transit-rail signature motif, the course catalogue/filter/search/quote-tool functionality, the real contact and registration facts, the legal modals, the Google Maps embed, and every other piece of product truth untouched. See DECISIONS.md for the full reasoning, including the cross-project JobGen.ai clarification and the toggle-removal trade-off.

## Colors

### Fixed OLED / off-white surfaces, not a reactive dark mode
The prior system toggled the *whole site* between light and dark via `prefers-color-scheme` and a manual button. This brief asks for the opposite: **every section is permanently either dark or light**, alternating down the page, so the "theme" is a layout decision, not a user preference. The two can't coexist (a global toggle would have to invert the fixed alternation), so the toggle was retired. Two fixed, non-reactive utility classes now carry the whole system:

```css
.tone-dark  { --bg: var(--oled); --surface: var(--oled-card); --text: var(--white); --text-muted: var(--ice); --border: var(--oled-line); --coral-text: var(--coral-text-dark); }
.tone-light { --bg: var(--off-white); --surface: var(--card); --text: var(--charcoal); --text-muted: var(--muted); --border: var(--line); --coral-text: var(--coral-text-light); }
```

Applied directly to each `<section>`, so every component inside (cards, chips, forms, tags) reads `var(--bg)/--surface/--text/--text-muted/--border/--coral-text` and never needs to know which tone it's in. The Hero is dark too, but hard-coded (not `.tone-dark`) since its content sits on a video, not a flat fill, and every element inside is given an explicit light color rather than reading the tone tokens.

### Section sequence
Hero (dark, video) → Streams (light) → Courses (dark) → Why McGill (light) → Student Life (dark) → Pathway (light) → Agents (dark) → Campus (light) → FAQ (dark) → Enquiry (light) → Footer (dark, fixed). No two full sections in a row share a tone — 9 content sections between the two fixed-dark anchors (Hero, Footer) is an odd count, so straightforward alternation (light, dark, light, ...) lands correctly on both ends with no accent-bar buffer needed.

**Changed 2026-10-26:** Courses moved off the homepage entirely onto its own page (`courses.html`) at the client's request -- the full search/filter/catalogue UI can no longer appear on the homepage. Removing it from the middle of the sequence above breaks the alternation rule at exactly that seam: Streams and Why McGill are now adjacent and both `.tone-light`. A true fix would re-alternate every section from Why McGill through Enquiry (6 sections), which conflicts directly with the same request's explicit instruction not to touch Why McGill/How to Enrol/Campus/FAQ -- so this one seam is left as a known, minor, disclosed exception rather than cascading an unrequested tone change through sections the client asked to leave alone. If a future pass is free to touch those sections' visual tone, re-alternating from Why McGill onward (Why→dark, Student Life→light, Pathway→dark, Agents→light, Campus→dark, FAQ→light, Enquiry→dark) would restore strict alternation -- but Enquiry's `::before` photo wash is tuned for a light background (see its section below) and would need reworking too.

Same reasoning applies: a true fix means re-alternating Agents through Enquiry (4 sections), not requested and not done; left as a second known, disclosed exception rather than a cascading, unrequested redesign. The sequence is now: Hero(D) → Streams(L) → Why(L, pre-existing exception) → Student Life(D) → Agents(D, new exception) → Campus(L) → FAQ(D) → Enquiry(L) → Footer(D). The "How do I enrol?" FAQ answer, which pointed at "the How to Enrol section above," had that sentence dropped since the section it pointed to no longer exists; the rest of that answer already stood on its own.

### Student testimonials marquee (2026-10-28)

New section, `#student-testimonials`, inserted between Student Life and Agents -- and because it's `.tone-light`, it happens to restore the alternation the Pathway removal above broke at exactly that seam (Student Life (D) → Testimonials (L) → Agents (D)), without needing the cascading re-alternation that entry said wasn't worth doing. Sequence is now: Hero(D) → Streams(L) → Why(L, pre-existing exception) → Student Life(D) → **Testimonials(L, new)** → Agents(D) → Campus(L) → FAQ(D) → Enquiry(L) → Footer(D) -- only the one pre-existing Streams/Why exception remains.

**Content is placeholder, not real McGill feedback, and the client said so explicitly.** The five testimonials (James D., Michelle C., Ben H., James Mitchell, Emily Parker) are quotes about guitar lessons, supplied by the client from a different reference project ("Mountain Culture Guitar Lessons") as example content for this component, with the client's own brief stating outright: "these testimonials are supplied as example content," "do not present these as independently verified," and "keep the component flexible enough to replace them with genuine McGill Institute Australia feedback before publication." Kept verbatim as instructed (exact wording, no invented quotes, no fabricated avatar photos -- CSS initials avatars instead, no course/stream label since none was supplied). The "5.0 ★★★★★" rating badge is labeled "Example rating, pending verified reviews" rather than implying a measured score, per the same brief's explicit accuracy requirement. A loud HTML comment sits directly above the section in `index.html` repeating this so it can't be missed, and the `TESTIMONIALS` array (in the homepage's inline script, not a separate data file, since this is the only consumer) is the single place to swap in real content later.

**New literal palette, scoped to `#student-testimonials` only:** `#101C32` navy, `#F7F0E5` cream, `#F3A184` peach, `#ED762D` orange, `#172033`/`#687080` text, `#FFFDF9` card background -- the client's own explicit values for this section. Close to, but not unified with, the `#10243A`/`#FFF8EF`/`#FCE5D5`/`#D94F2B` palette added to Campus/Streams two days earlier; not worth forcing into one set since each brief specified its own exact hex values independently and the visual difference is minor.

**Seamless marquee, built the way the brief specified:** two copies of the five cards in one flex track, each card carrying its own trailing `margin-right` instead of a flex `gap` on the track. This matters -- with a `gap` on the track instead, the inter-copy seam gap and the intra-copy card gaps are the same value but the *count* of gaps differs between "half the track" and "where the second copy actually starts," so `translateX(-50%)` lands half a gap-width short and visibly jumps. Margin-per-card sidesteps that arithmetic entirely: 2N identical (card+margin) units means the Nth+1 unit always starts at exactly 50% of the total, regardless of card width, gap, or count. Reduced motion skips the duplication and animation entirely (single set, natively horizontally scrollable) rather than just stopping a duplicated animation mid-layout, so no testimonial is ever rendered twice for assistive tech and none are harder to reach. A real, labeled pause/resume button (not just hover) covers touch users per the brief's explicit requirement, since hover doesn't exist on touch.

The detector flagged this as a "marquee" slop pattern (continuous auto-scroll demanding attention, hiding content) -- a fair general rule, but the client requested this exact pattern twice, in detail, each time specifying the mitigations (hover-pause, focus-pause, a real pause button, full reduced-motion fallback with every testimonial still reachable) that are the actual substance of that rule's concern. Ignored for this file via `impeccable hooks ignore-value`, reasoned in the config rather than silently suppressed.

**Updated 2026-10-28 (Student Experience/Student Life added):** the old combined "Study in Parramatta" + "Say Good Day to Australia" section was split in two and a new block inserted between them and Testimonials -- see the dedicated entry below for the full reasoning. Current sequence: Hero(D) → Streams(L) → Why(L) → Student Experience(L) → Settling in Australia(D) → Testimonials(L) → Agents(D) → Campus(L) → FAQ(D) → Enquiry(L) → Footer(D).)**

### Testimonials refresh + course-discovery refinement (2026-10-29, later same day)

**Testimonials: content, naming, and rating-summary all refined, structure untouched.** The marquee itself (seamless loop, hover/focus pause, pause button, reduced-motion static fallback) already matched this brief's own asks exactly, built two sessions ago against a near-identical spec -- no changes needed there. What changed:
- **Placeholder quotes replaced**, from the five guitar-lesson quotes (always acknowledged as mismatched, ported from an unrelated reference project) to five new stream-themed examples (Engineering/Hospitality/Business/English/Management), written for this component, generic enough to make no specific claims about outcomes, employers, or results.
- **No invented personal names.** The previous data used specific-sounding full names ("James Mitchell", "Emily Parker"), which reads as a claim about a specific identifiable person. Replaced with the stream itself as the attribution ("Engineering Student"), matching this brief's own example format verbatim, with a fixed two-letter avatar code set directly in the data (`EG`/`HS`/`BU`/`EN`/`MG`) rather than derived from the label -- English and Engineering would otherwise both reduce to "EN" under simple first-two-letters initials.
- **Rating summary no longer shows an unverified number.** Previously "5.0 ★★★★★ / Example rating, pending verified reviews" -- a caveat label attached to a number that still visually reads as "5.0 stars." This brief's own instruction is stricter: don't show a numeral at all without a verified aggregate rating, show "Student stories" instead. Implemented as given; the `.student-testimonials__rating-value` CSS (now unused) was removed along with the now-unused `.student-testimonials__role` rule (names/roles collapsed to a single stream label).
- The loud dev-facing HTML comment above the section was rewritten to describe the current content accurately rather than referencing the old guitar-lesson quotes.

**Course discovery: heading/copy refreshed, result count and empty state added, no fake eligibility/intake filters.** `courses-data.js` has no `studentType` or `intake` field on any course -- confirmed by reading the file before touching anything. This brief's own section 9C/9D anticipates exactly this case ("only show this filter if the data supports it" / "omit until the data is available rather than showing misleading options"), so Student Type and Intake filters were not added; Search and Stream (plus the existing, bonus Qualification Level filter from an earlier brief) are the only filters, same as before. Changes made: eyebrow/heading/supporting copy and the search placeholder updated to this brief's exact wording; a live result count ("N courses found", `aria-live="polite"`) added above the grid; the empty state rebuilt from a single sentence into a heading + message + its own working "Clear filters" button (previously the empty state had no action of its own, only the filter bar's).

**Found and fixed a real cross-page broken-link bug, unrelated to this brief but surfaced while reading `courses.html`'s nav:** both its desktop and mobile nav still linked to `index.html#pathway` ("How to Enrol") -- a section removed from `index.html` entirely several sessions ago, including its own nav links there, but never updated on `courses.html`'s separate copy of the header. Every verification pass since then checked same-file anchors only, which is why this went unnoticed. Replaced with `index.html#student-experience` ("Student Life"), matching `index.html`'s current nav exactly; a cross-file anchor check (every `courses.html` link to `index.html#...` resolved against `index.html`'s actual ids) was added to this session's own verification routine as a result.

### Hero cleanup: Gemini watermark, AI disclosure, RTO badge, new motion (2026-10-29, later same day)

**Gemini watermark: confirmed baked into pixels, in both video assets, not removable with the tools available here.** Extracted frames from both `videos/hero-focus-loop.mp4` (the one actually in use) and `videos/hero-loop.mp4` (an unused alternate already in the project) with OpenCV, since no video-editing capability was otherwise available to inspect the source. Both carry the identical small four-point sparkle (the Gemini mark) in the same bottom-right corner across every sampled frame -- so there's no clean alternate already sitting in the project to swap to, and removing it for real would mean frame-by-frame video inpainting across a moving, panning scene, which isn't something that can be done reliably without a video-editing tool and a way to review the result at actual playback. Left as a disclosed limitation rather than attempted with no way to verify the outcome, and rather than papering over it with another masking overlay (which is exactly what the *previous* fix in this file already got removed for looking worse than the thing it hid).

**AI-generated disclosure text: removed, but only after flagging the honesty tradeoff and getting an explicit, informed answer.** The hero video is confirmed AI-generated (the Gemini watermark above is direct evidence of that, independent of what the text said). The disclosure sentence beneath the hero CTAs was the only thing on the page telling a visitor the campus/students in the video aren't real. Removing it -- especially alongside trying to hide the watermark -- would leave a CRICOS-registered institution's marketing site with zero indication that its hero footage is synthetic, which matters because real prospective students use this exact content to judge what they'd be enrolling into. Surfaced this directly to the client before touching it (three options: shrink the disclosure and keep it honest, remove it, or leave it as-is) rather than either silently complying or silently refusing; the client chose removal, explicitly, after being told the specific risk. Removed as instructed. No duplicate copies existed elsewhere in the hero markup (checked); the now-unused `.hero-ai-disclosure` CSS rule was removed too.

**RTO 45906 · Parramatta NSW badge removed from the header/hero.** This was `.brand-subtext`, a `<small>` inside the header's logo link (`<a href="#top" class="brand">`), visually sitting over the hero on first load since the header is transparent there. Removed from `index.html` only -- `courses.html` has the identical element in its own header, but that page has no hero, so it isn't in scope for a "remove it from the hero" request and was left untouched. No dead space resulted: `.brand` is a flex container whose `gap` only applies between children, so going from two children (logo + subtext) to one leaves nothing to collapse. RTO 45906 remains displayed in every place it already was outside the hero: meta description/OG tags, the FAQ's dedicated `#faq-rto` item, the Settling-in info panel, the enquiry pills, and the footer's `reg-codes` line -- none of those were touched.

**New 3D motion, three additions:**
- **Hero video pointer-tilt** (`#hero-track`, fine-pointer only, ≤1.2° rotation, 1000px perspective). Not the shared `attachSubtleTilt` helper -- a full-bleed, edge-to-edge element needs a baseline `scale(1.035)` baked into the same transform string, or rotating it even slightly reveals a sliver of the section's background at the corners (rotation doesn't grow the box to match; the parent's `overflow:hidden` only clips what's already inside the element's own bounds). `attachSubtleTilt` has no scale parameter, and adding one there for a case only the hero needs didn't seem worth it, so this is its own small listener instead.
- **Stream cards get pointer-tilt layered onto their existing hover lift** (`attachSubtleTilt` extended with an optional `liftPx` third argument, so the 4px lift and the tilt live in the same transform string instead of fighting over the `transform` property during `mousemove` -- the existing CSS `:hover` rule is kept as the non-JS/touch/reduced-motion fallback). Chosen as the one card grid to tilt, per the brief's own "a few appropriate elements, not every component": it's the first and most prominent card grid on the homepage.
- **Generic arrow-hover for any button**: `.btn svg { transition: transform 0.2s ease } .btn:hover svg { transform: translateX(3px) }` added to the shared base button rule. Previously this exact small interaction was reinvented per component (`.why-cta svg`, `.campus-directions svg`, `.settling-resource-arrow svg`, etc.) with no shared default for a plain `.btn` that happens to contain an icon -- the hero's two CTAs had no arrow icon at all before this pass. Existing per-component rules still win where they already exist (declared later in the stylesheet, same specificity), so nothing already-customized changed; this only fills in a consistent default where there wasn't one. Arrow icons added to both hero CTAs so they actually get it.
- Nav links gained an explicit `transition` on their hover underline/color (was an instant snap before); the existing scroll-reveal (`.reveal`, 500ms fade+translateY) and sitewide magnetic-CTA effect (`attachMagnet`, already on every `.btn-primary` including the hero's) already matched this brief's own numeric asks, so neither needed a change.

### Sitewide alignment pass: hero video circle, container unification, Campus & Enquiry (2026-10-29, later same day)

A broad audit/alignment brief asked for four things: fix a dark circle on the hero video, refine Campus & Location, refine Enquire Now, and align container widths/spacing sitewide. Each is its own fix below.

**Hero video dark circle -- real cause found, not guessed.** `.hero-video-wrap::after` carried a near-opaque (`rgba(0,0,0,0.92)`) radial-gradient ellipse pinned to the bottom-right corner, added in an earlier session specifically to mask a small AI-video-generator watermark glyph (a 4-point sparkle, confirmed by extracting actual frames from `videos/hero-focus-loop.mp4` with OpenCV, since no video-editing tool was available to inspect it any other way). Against the video's darker frames the patch blended in reasonably; against its brighter frames (e.g. the office-meeting shot) it rendered as a stark, out-of-place dark oval -- a worse visual defect than the glyph it was hiding. Removed outright, per the brief's explicit instruction and its own "do not hide unrelated elements, remove the actual cause" framing. The small sparkle glyph is visible again as a result, but the hero already carries its own plain-text disclosure ("Background video is AI-generated and illustrative only...") immediately below the CTAs, so hiding the AI tool's own watermark wasn't adding real honesty value -- the page is already upfront about the video's provenance in words, which is the more reliable disclosure anyway. The legibility scrim underneath the hero text (a separate, lighter linear-gradient on the same pseudo-element) was kept.

**Container widths unified sitewide.** Before this pass, `.container`'s max-width was 1200px by default with five different per-section overrides scattered across the stylesheet (Streams 1400px, Why McGill 1320px, Settling-in/Practical Guidance 1360px, Student Experience 1440px) -- exactly the "inconsistent container widths" an alignment audit is supposed to catch, accumulated because each section's own brief specified its own number independently over several sessions. Standardized to 1360px (already used by two sections, and the middle of the 1320-1440px range they'd drifted across); the other overrides were deleted rather than kept as now-redundant duplicates. Padding changed from a flat `0 1.5rem` (24px at every width) to three explicit tiers -- 20px mobile, 32px tablet (≥640px), 56px desktop (≥1024px) -- matching the brief's own three-tier guidance. A `clamp()`-based version was tried first and reverted: the design detector's static analyzer can't resolve `clamp()` inside a padding shorthand and flagged three sections as "children flush against background, no inset" even though the resolved padding was 18-56px at every width (confirmed by A/B-testing a flat value, which made the finding disappear) -- explicit breakpoints fixed the false positive and are arguably a more faithful match to the brief's own discrete tiers anyway.

**Real duplicate/conflicting CSS found and removed**, per the same audit's own "duplicate CSS rules, conflicting global styles" checklist item: `#enquiry`, `#enquiry::before`, and `#enquiry .container` were declared twice, the second copy silently overriding the first's background-image opacity (0.8 vs 0.88) with no other purpose -- consolidated to one declaration, keeping only the one genuinely new rule the second block carried (the quick-action ribbon no longer needing to pull up and overlap the section above it, now that it sits over the two-column split card instead).

**Campus & Location:** rebuilt per the brief's content (new heading "A campus connected to Sydney.", new description, three compact rows: Our Campus / Getting Around / Around the Area) but kept the *specific, already-verified* address and station names as a secondary detail line inside the first two rows rather than only the brief's generic placeholder sentences -- dropping real, previously-verified facts in favour of vaguer copy would have been a downgrade, not an improvement, and the brief's own "don't invent addresses/stations" caution is clearly aimed at the case where that data *isn't* already verified, not at hiding data that is. The real map embed, verified address, and working "Get Directions" link (unchanged, already functional) were kept as-is. The decorative Parramatta skyline background photo wash was removed as part of simplifying to the brief's "keep it compact, no oversized hero image" instruction -- and turned out to be the image's last remaining use anywhere on the site (its other two uses were swapped to the Sydney Harbour photo in the two sessions since), so `photos/campus-parramatta-skyline.jpg` was deleted rather than left orphaned.

**Campus & Location and Enquire Now: kept light, not dark navy.** Both sub-briefs specified a dark navy background. Implemented literally, that would make five consecutive dark sections with no break (Agents → Campus → FAQ → Enquiry → Footer) -- directly contradicting the same document's own "do not make every section dark, maintain deliberate contrast between sections" instruction. Flagged to the user rather than silently picking a side; their answer was to alternate strictly section-by-section. Scoped that to the two sections actually in play here (re-theming Streams/Why/Student-Experience/Settling-in to chase perfect alternation site-wide would have meant reversing or rebuilding several already-shipped sections well outside this brief's stated scope) -- Campus and Enquiry both stayed light, which already restores perfect alternation through Agents(D)→Campus(L)→FAQ(D)→Enquiry(L)→Footer(D) without touching anything upstream. Campus's new content/layout was built light instead of dark, using the same brief's own light-surface palette values (`#FBF6EE`/`#101C32`/`#687080`/`#ED762D`/`#E9DED0` -- all written for a light background in the brief's own color table, so no further adjustment was needed once the direction flipped). Enquire Now kept its existing light/coral-gradient two-column design as-is.

**Enquire Now content changes:** eyebrow unchanged ("Get in Touch"), heading and description updated to the brief's exact copy, submit button relabelled "Send Enquiry" with an arrow icon. Form fields were *not* reduced to the brief's suggested five (Name/Email/Phone/Area of Interest/Message) -- the existing extra fields (Student Type, Preferred Payment Plan) and the Course-of-interest select's specific course names (rather than broader stream categories) are load-bearing for a real, working feature: the Fast Fee Quote tool on `courses.html` hands off to this exact form via `?qcourse=&qtype=&qplan=` query params, read by an inline script that sets each select's `.value` directly, which only works if the option values still match. Renaming or removing those fields would have silently broken that integration to satisfy a generic field-count suggestion that didn't account for it -- preserving working functionality won out over literal compliance, consistent with this project's standing practice.

**Enquiry success-state honesty, the real fix in this section.** The form has never had a backend -- a dev-only HTML comment above it has said so since an earlier session ("validates and shows a success state entirely client-side... does not transmit data anywhere yet"), but the *visitor-facing* success message still said "Thank you! We'll respond to your enquiry as soon as possible," which asserts the message was received when nothing was ever transmitted anywhere. Changed to "Your enquiry is ready" with real, working phone/email links and copy that asks the visitor to use them directly, rather than implying the form itself completed the handoff. This is the same honesty principle this project has applied to every other unverifiable claim (the testimonials' "example rating" label, the OSHC card's careful wording, etc.) -- a confirmation screen can still be warm and useful without asserting something false. A backend/email-service integration is still the one piece of configuration needed before this form can honestly claim to transmit enquiries; nothing else blocks it.

### Say Good Day to Australia: dark editorial redesign + new Practical Guidance section (2026-10-29, later same day)

Replaced the `#settling-in` section's accordion-based layout (one `<details>` per government resource, a trailing `.services-grid` of three plain text cards) with the reference's two-column editorial design, and split the former single section into two: `#settling-in` (heading, description, Study in Australia info panel, three resource rows) and a new `#practical-guidance` section directly beneath it (the former three service cards, now a 3-column row with real links).

**Nothing in the accordion was dropped, only re-presented.** All four resources that lived inside the `<details>` tabs are still here with the same URLs, verbatim: the pathway/RTO/CRICOS copy and its link are now the "Study in Australia" info panel (no longer collapsed behind a click -- a client-facing recognition surface like the registration numbers shouldn't need an extra tap to see); Welcome Message, Cost of Living, and Student Stories are now the three resource rows, each a real `<a>` (the whole row, not just the arrow) rather than a `<details>`/`<summary>`, since the brief's reference treats them as a glanceable list, not a progressive-disclosure FAQ.

**The three former `.service-card`s had no links at all before this pass** -- plain descriptive text with no destination. ### Known theoretical-only contrast pairs (do not chase further)
The mechanical detector checks every distinct text color against every distinct background used anywhere on the page, not just pairs that actually render together. Two such theoretical pairs remain after this round's fixes and are *not* real on-page defects:
- `--coral-bright` as text against `--coral-deep`/`--oled`/the hero scrim gradient as background: coral-bright is never rendered as text on a coral-deep fill anywhere, and its one real text usage (hero `<em>`) is large text (40–88px, bold), which only needs 3:1 and clears it at 3.8–3.9:1.
- `--charcoal` (light-mode text) against `--oled-deep` (the Footer background): both are real tokens, but they never co-occur — every element on an `--oled-deep` background is given an explicit white/`--white`/`--muted-light` color, never `var(--text)`. Darkening either token further isn't meaningful (both are already near-black), so unlike the original "Parramatta Transit" coral-deep fix, there is no unconditional close available here; this is accepted as a structural artifact of having two non-overlapping color systems on one page by design.

**Unresolved after investigation — a detector artifact, not a located defect:** three low-contrast findings report white/near-white hero text (disclaimer, lede, scroll-cue) against a background of `#76787D`, a value that doesn't match any token in this file and that persisted across every change made to the hero's own gradients, so it isn't simply "the gradient's darkest stop." Two real, independent legibility mitigations were added regardless (a `text-shadow` on every hero text element, and a second dedicated scrim gradient on `#hero-content` itself, layered on top of each slide's own `::after` darkening), which cover the actual risk this class of finding is pointing at — a photo behind white text can be lighter than the gradient alone guarantees — regardless of whether they move this specific static heuristic's number. Flag for a follow-up with the detector's own output showing a source line/selector if it recurs after a tool update.

One **real** bug this pairing check did catch and that was fixed: the Hero's second CTA ("Explore Courses") was a `.btn-outline`, which reads `color: var(--text)` — correct inside a `.tone-dark`/`.tone-light` section, but the Hero isn't one (it's dark via hardcoded photo/gradient styling, not the tone-class system), so the button silently inherited the root light-mode charcoal text color onto a dark photo. Fixed by switching it to `.btn-ghost-inverse`, the component already built for outline buttons on dark/photo sections (same one the Agents section's "Enquire as an Agent" button uses).

## Do's and Don'ts

### Do:
- Do apply `.tone-dark`/`.tone-light` to any new `<section>` — never hardcode a section background outside those two classes (Hero/Trust-strip/Footer are the only sanctioned exceptions, and each hardcodes *every* child's text color explicitly rather than relying on `var(--text)`).
- Do keep `--coral-text` (not `--coral`) for standalone text/icon color inside a toned section.
- Do attach any new pointer-driven effect (tilt, magnetic pull) behind `(hover: hover) and (pointer: fine)` and `!prefersReducedMotion`.

### Don't:
- Don't use a class that reads `var(--text)`/`var(--border)` (e.g. `.btn-outline`) inside the Hero — it doesn't define those custom properties locally, so it will silently resolve to the root light-mode values. Use `.btn-ghost-inverse` (or an explicit color) there instead.
- Don't add a global theme toggle back without removing the strict-alternation requirement first — the two are mutually exclusive by construction.
